  - 时间点**没动** → **唤醒原来那条 worker** → 从暂停处接着跑，**一格都不重抽**
  - 时间点**动了** → 当前这轮先跑完，跑完**自动再起一轮**（`_restart_after_done`）：
    新增的时间点照常抽，已截好的按「(文件, 时间点)」**跳过**
- 跳过键是 **(行号, 时间点)** 而不是列号 —— 列号会随增删时间点而移位。
- **不直接重起 worker**：老 worker 可能正在抽某一格，两条 worker 同时写
  同一个 PNG 会写坏 → 所以改成「老这轮跑完 → 自动起新一轮」。
- 踩过的坑: 「已经截好」的判定看的是**模型里的状态**，而状态是消息驱动更新的
  → 刚抽完还没记进模型的那一格会被重抽一遍 → 暂停/继续前都先
  `_drain_pending()` 把积压的消息处理掉。

**同日第八轮（定点截图: 删时间点 + 逆时间点）**：

- 用户两条新需求: ① 时间点可以删（**含默认的**）② 增加时间点类型（正/逆）。
  问了三处会改变可见行为的细节，用户答: 类型**在添加的时候**选（默认前两个正、
  **第 3 个逆**）/ 逆的文件名**加 R 标记** / 逆时间点超片长 → **那一格标失败**。
- **时间点变成一组** `[类型标记][输入框][×]`；类型是静态标签不是下拉框
  （在添加时定，之后只能删掉重来）；「+」按钮改成**带菜单**（正时间点/逆时间点）。
- **逆时间点的实际时刻 = 视频时长 − 输入值**，**逐行算**（每个视频时长不同）→
  `VideoInfo` 加了 `duration_seconds`（**原始秒数**，不用 `duration` 那个格式化
  字符串反解 —— 会丢小数）。
- **R 标记**贯穿: 时间点字符串 `R00:01:00:00` → 文件名 `…_t3_R00-01-00-00.png`
  → 解析回来还是带 R → 表头渲染成 `T3: 逆 00-01-00-00`。旧的不带 R 的照旧能读。
- **规格变更**：产品文档 §6 #28「截图弹窗**没有删除时间点按钮**」是当初的刻意
  决定；那 39 行是「实施者不许自己动」，但**这次是用户明确要求** → 按用户要求
  改写，并在 §6 那行注明变更来源 + CHANGELOG v4.3 记明。
- 顺带改了三个旧脚本的夹具（`make_info` 加 `duration_seconds`）—— 默认第 3 个
  时间点变成逆的之后，没时长的夹具会让那一格失败。

**同日第七轮（重名加后缀）**：

- 用户要「重名后自动加后缀」。核心函数 `unique_poster_path(output_dir,
  base_name, ext, taken)`：按顺序找**第一个空位** `名字.ext` /
  `名字_1.ext` / `名字_2.ext` —— **不链式**（app 里移动文件那个
  `a_1 → a_1_1` 的老毛病，§6 #23）；并把占到的名字**记进 `taken`**。
- 两种重名都让开：磁盘上已有的文件、**本批次里**另一条线程刚占的名字。
- **并行下载下的原子性**：check + 占位必须原子 → `download_poster(...,
  taken=..., lock=...)` 把锁传进去，但**网络下载在锁外**（不然并行就没意义）。
- 行为变更：**同名不再覆盖**（原来会覆盖），磁盘上已有的原文件保持不动。

**同日第六轮（并行下载）**：

- 用户要求把**串行**下载改成**3 张并行**。实现：`_poster_worker` 从
  「一条线程按顺序下」改成「**一个任务队列 + `POSTER_PARALLEL`(=3) 条
  工作线程**各自取任务」—— 不是「开 3 个线程各下一段」（那样进度条会乱）。
- 计数器（已完成/成功/失败/错误列表）三条线程共用 → 拿一把 `threading.Lock`。
- 进度消息里的 done 改成「**已完成张数**」（不是任务序号），进度条照旧。
- 暂停语义不变但范围变大：在飞的最多 3 张下完就不再开始新的。
- 断言：`threading.Barrier(3)` —— 三张都到齐才放行，串行的话第一张等到
  超时炸掉 → 红了。这条真的证明了「同时下 3 张」，不是看代码猜的。

**同日第五轮（两个功能解耦）**：

- 用户指出：「下载海报」与「视频检测」是**两个完全不同的功能**，只是入口放在了
  同一个界面上 —— 弹窗开着**不该冻住主窗口**。
- 改动：`PosterDialog` 由 `setModal(True)` + `exec()` 改成 **`setModal(False)` +
  `show()`**；主窗口用 `self._poster_dialog` 保住引用（非模态窗不保引用会被
  Python 回收掉），再点按钮只 `raise_()` 不开第二个。
- **顺带修掉一个真 bug**：`finished(int)` 带一个结果码，槽写成不接参数的
  → PySide 抛「takes 1 positional argument but 2 were given」→ 关窗后引用
  永远清不掉。是断言（`关掉弹窗 → 引用清空`）查出来的。

## 5. 流程约定（下次照做）

- **派发方式**：subagent-driven。实施者 → 任务审查 → （有问题）返工轮 → scoped 复审 → 完成。
  每个任务一轮**任务审查**；返工轮后一轮 **scoped 复审**（只审那批 findings + fix diff）。
- **模型**：`sonnet` 做实施/审查；`opus` 用于大改动或架构判断。**注意**：短别名 `sonnet`
  有时解析到会话模型（MiniMax-M3），撞过 429（Token Plan 上限）；撞了就换 `fable` 重派。
- **CRLF**：`video_checker.py` 是 CRLF，**绝不能用 Python `open().read()/write()` 改**
  （整篇转 LF → 约 2000 行幽灵 diff）。只用 Edit 精确替换；改完验
  `python3 -c "d=open('video_checker.py','rb').read(); c=d.count(b'\r\n'); print('bare LF:', d.count(b'\n')-c)"`
  → 必须是 `0`。**新建的文件一律 LF**。
- **断言脚本**：`docs/superpowers/specs/<date>-<topic>-assertions.py`，LF，退出码 0 = 通过。
  没有 pytest。Tk 脚本用 `TkinterDnD.Tk()`；Qt 脚本用 `QApplication`，
  **且必须在 `from video_qt import ...` 之前建**。
- **Qt 脚本在本机无显示环境** → 用 `QT_QPA_PLATFORM=offscreen`。会打一条已知的字体族
  警告到 stderr（**来自我们自己的路径**：`QFontMetrics(QFont())` 触发的 'Sans Serif'
  不存在）—— 不在范围，但**测试环境的字宽与生产不一致**，像素级断言跑的是另一套度量。
- **改计划文件**：用 Edit 工具 + 唯一锚点。**不要用 `s.index()` 找裸标记** —— 我这么干过
  一次，匹配到的是**前一个任务**的同名 Step，把 760 行删了。改完立刻
  `grep -n "^### Task"` 校验标题还在。
- **每次派发前**：跑一遍「依赖盘点」—— 哪些断言脚本 import 了即将被删的东西。
  **不要照抄别人的结论，自己 grep 一遍**（我漏查过一次 GUI 类依赖，边界定错了）。
