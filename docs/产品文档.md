# 视频码率检查器 — 产品文档

版本: v4.2（GUI 层是 PySide6 —— v4.0 换的 GUI 层，v4.1 追加「查看已有截图」，v4.2 追加「下载海报」；开发分支 `refactor/qtableview` 已快进合并进 `main`，分支已删 —— **`main` 即当前版**）
日期: 2026-11-04（v4.2 发布；v4.1 是 2026-11-03，v4.0 是 2026-10-27）
性质: **框架无关**的行为规格。任何实现（当前的 PySide6 版 / 旧的 Tkinter 版）都必须满足本文。

---

## 1. 定位与用户

**一句话**：批量扫描视频文件，用 ffprobe 读出技术参数，按用户设定的阈值判定「达标 / 不达标」，并把文件批量移动到目标目录；另有一个定点截图功能，用于按时间点抽帧做肉眼比对。

**使用者**：做视频批量质检 / 归档的运营或后期人员。典型场景是手上有一大批待检文件，需要快速筛出达标的移走，不达标的留原地。

**平台**：Windows 桌面工具，打包成单文件 exe（打包目标平台仍是 Windows）。2026-10-27 修掉 ffprobe 的平台守卫后，源码本身也能在 macOS/Linux 上跑（见 §7）。

---

## 2. 核心概念

| 概念 | 含义 |
|---|---|
| **扫描** | 对一个目录（可递归）或一组被拖入的文件跑 ffprobe，产出每个文件的技术参数 |
| **达标** | 码率 **且** 采样率 **同时** 达标。两个阈值都满足才算达标 |
| **结果行** | 一个文件对应表格里的一行 |
| **派生路径** | 迁移地址 / 截图地址 —— 由「文件路径」派生出，默认各带一个固定子目录（`checked` / `snapshot`） |
| **定点截图** | 按若干时间点抽帧成 PNG，网格化展示供肉眼比对 |
| **海报下载** | 按一份清单文档（csv/xlsx）里的海报链接，把海报图批量存到指定目录 |

## 3. 功能范围

### 3.1 扫描

- 输入：目录路径（配合「子文件夹」勾选决定是否递归）**或** 拖入窗口的一组文件
- 扩展名白名单 36 个（`.mp4 .mkv .avi .mov .wmv .flv .ts .m2ts .mpg .mpeg .webm .3gp .m4v .vob .ogv .rm .rmvb .asf .divx .f4v .mxf .mts .m1v .m2v .mpv .qt .y4m .nut .dv .tp .trp .hevc .h264 .h265 .264 .265`），比较大小写不敏感
- 递归用 `os.walk`（不跟随符号链接）；非递归用 `os.listdir`，**不排序**（保持系统顺序）
- 目录不存在或不可读 → 视为空结果，**不报错**
- 无视频流的文件 → 跳过（不进表格）
- ffprobe 失败 / 超时（30s）→ 静默跳过该文件，**不计入「共 N」，也不提示**
- 扫描过程可随时点「开始检测」取消（按钮变「正在停止...」）

### 3.2 达标判定

- 码率阈值默认 `30000` kbps，采样率阈值默认 `48` kHz，两者都可改
- 阈值必须是**正数**；非法输入弹错误框并拒绝开始扫描
- 判定：`bitrate_kbps >= 码率阈值` **且** `sample_rate_passing`
- **边界含等于**：正好 30000 kbps 算达标
- **无音频流视为采样率达标**（`sample_rate_passing = True`）
- 阈值是**扫描开始时的快照**：扫描中途改阈值，已扫的行不重算

### 3.3 表格展示

12 列（序号 + 11 个数据列），详见 §4.2。核心要求：

- 达标行**全部文字绿色**；不达标行**只有** title、result（+ 码率不达标时的 bitrate，+ 采样率不达标时的 audio_sample_rate）是红色，其余保持默认色
- **不画整行底色**，只有文字前景色
- 序号列固定 45px、不可排序、不可拖宽、**永不染色**
- 标题列显示相对路径 `./A/B/name.mp4`；跨盘符时显示绝对全路径
- 可排序列 4 个：结果 / 码率 / 帧率 / 采样率
- 点表头排序，**三态循环**：无 → 升序 → 降序 → 无；切到别的列重置为升序
- 排序箭头是**表头文字的后缀**（`码率(kbps) ▲` / `▼`），非活动列无箭头
- 列宽可拖拽调整，最小 20px；表头文字随列宽重新截断
- 文本过长按像素截断并加 `...`（三个 ASCII 点，不是 `…`）
- 悬停**被截断**的单元格才弹 tooltip 显示完整值；未截断的不弹

### 3.4 文件迁移

- 两个入口：「移动达标文件」/「移动全部文件」
- 目标目录**点按钮时才创建**（扫描与浏览阶段绝不建目录）
- 移动前弹确认框，列出数量与目标路径
- 目标已存在同名文件 → 追加 `_1`、`_2`… 直到不冲突
- 失败清单在结果框里列出，**最多 20 条**
- 移动的是**移动不是复制**
- 移动后表格不刷新（行仍显示旧路径）

### 3.5 定点截图

- 从主窗口「定点截图」按钮打开，模态
- 截图地址默认 `<文件路径>\snapshot`，可在弹窗内改；「浏览」选的是**父目录**，套一层 `snapshot`
- 默认 3 个时间点 `00:00:07:24` / `00:00:08:00` / `00:01:00:00`；`+` 按钮追加（默认 `00:00:00:00`）；**没有删除按钮**（清空输入框即删除）
- 弹窗默认宽 **1380px**（高 700px）：3 个时间点的缩略图**一屏放得下**，不出横向滚动条 —— 序号 45 + 标题 300 + 3 × 328 = 1329px，窗口宽 = 1329 + 边距 12 + 纵向滚动条 18 = 1359，取 1380（余量 ~21px）。**代价：1366px 宽的笔记本屏幕放不下。**
- 时间点格式 `HH:MM:SS:frame`，MM/SS ∈ [0,59]
- 时间点输入框**紧挨「时间点:」标签**依次排列（第一个入口在标签右侧 ~4px），「+」按钮在行的**最右**（与 Tk 版一致）
- 双击时间点输入框只选中所在的那一段（HH / MM / SS / frame），不整段全选
- 网格：行 = 文件，列 = 时间点；单元格显示抽出的帧
- 单元格三态：加载中（`…` 蓝）/ 成功（缩略图）/ 失败（`×` 红）
- 点已成功的缩略图 → 弹出放大窗口看 640px 原图（**从磁盘重新加载**，不是复用内存里的）
- 抽帧用 ffmpeg，输出 **640px 宽 PNG** 存盘，弹窗里显示 320px 缩略图
- 抽帧进行中点关闭 → 二次确认；**不 kill 已启动的 ffmpeg 进程**
- **「查看已有截图」按钮**（第一行，「开始截图」左边）：把截图地址里**已有**的截图按「视频标题 + 时间点」回填进网格
  - 文件名规则 `{视频标题去扩展名}_t{序号}_{HH-MM-SS-FF}.png`（`:` 换成 `-` 是因为 Windows 不许文件名带 `:`）；不符合规则的图片**忽略**
  - 只扫截图地址的**第一层**（不递归）
  - **时间点列取自目录**：目录里实际存在哪些时间点就建哪些列，按时间先后排序；**与时间点输入框无关**（输入框是「开始截图」用的，不被改动）
  - 只展示与**本次所选视频**匹配的图；没匹配到的格子**留空**（不是「…」）
  - 同一个（视频, 时间点）有多张时取**修改时间最新**的那张
  - **只读**：不抽帧、不写文件、**不建目录**；截图地址不存在时只提示
  - 扫描与解码跑在**后台线程**里（界面全程可动）；底栏状态行**实时**报进度：`分析中 {done}/{total} 个文件` → `加载中 {done}/{total} ({当前视频名})` → `已有截图: …`
  - 加载期间「开始截图」「查看已有截图」都禁用；加载中关窗**不弹二次确认**（只读操作，没有副作用），后台线程自行退出
  - 「开始截图」的行为**一个字都不改**（仍然抽帧、仍然覆盖旧文件）；抽帧进行中「查看已有截图」禁用

### 3.6 拖拽文件

- 接收区域是**整个表格区**（含表头与正文），空表也能接住
- 拖入文件 → **立即开始扫描**（不需要再点「开始检测」）
- 路径框填第一个被拖入文件所在目录（不含文件名）
- 迁移地址 / 截图地址跟随该目录
- 记住拖入的**具体文件列表** → 下次点「开始检测」扫的是这批文件而非目录（除非用户手动改过路径框）
- **拒绝规则**：
  - 扫描中拖入 → 「正在检测中，请等待完成后再添加文件。」
  - 阈值非法 → 对应的错误框（与点「开始检测」同一套校验）
  - 全是非视频扩展名 → 「没有找到视频文件。」
  - 拖入**目录**不生效（只按扩展名过滤，目录没有扩展名）
- 非视频扩展名的文件**静默跳过**，不逐个提示

### 3.7 清除记录

点了会清：结果列表、表格内容、达标计数、**迁移地址**、**截图地址**、拖拽留下的文件列表。
点了**不会**清：码率 / 采样率阈值输入框。

扫描中点 → 「正在检测中，请等待完成后再清除。」

### 3.8 下载海报

按用户提供的**清单文档**（csv / xlsx）里的海报链接，把海报图批量下载到指定目录。

- **入口**：主窗口 Row 2 行尾，「定点截图」右边
- **不需要先扫描** —— 它吃的是一份文档，不是视频
- **文档**：可手输路径，也可「浏览」选；**只支持 .csv / .xlsx**
  - **.xls（旧版二进制）不支持** → 提示「请用 Excel/WPS 另存为 .xlsx 或 .csv」
  - csv 编码自动识别（utf-8 / utf-8-BOM / GBK）
- **版面**（2026-11-04 用户定的次序）：
  - 第 1 行：`文档: [路径] [浏览] [开始分析]`
  - 第 2 行：`命名来源: [下拉] 海报地址: [路径] [浏览]`
  - 第 3 行：`海报命名规则: [模板] [☑首行为字段名] [开始下载]`
  - 第 4 行：`海报链接字段: [☑][☑][☐]…`（**单独一行**，在「海报命名规则」行之下）
- **两个来源是两回事**（2026-11-04 用户踩过坑）：
  - **命名来源** = {clipname} → 只决定**海报地址**（文件夹名）。整个片子共用一个值。
    界面上的下拉框，用户可改；自动猜按列名（剧名 / 片名 / 专辑 / clipname…），
    没有列名线索就找一列「所有行都一样」的
  - **{partname}（文件名）取自哪一列 → 程序自动挑**，界面上没有下拉框。
    挑的规则：列名像分集 / 集名 / 期数 / partname… **且该列逐行不同** →
    否则挑一列**逐行不同、且是文字**（不是数字列）的非链接列 → 否则挑一列逐行不同的列
  - 这一列必须**逐行能区分开** —— 两者混成一个字段的话，所有海报算出同一个文件名，
    后下的把先下的**覆盖掉**（用户踩过：表里的剧名每行都一样）
  - 挑中的是哪一列，在**状态行**里报出来：`文件名取自「集名」`
- **开始分析**：读文档 → 预览**前 5 行**（全部字段）→ 猜出字段（用户可改）
  - **海报链接字段可以有多个**：文档的**每一列**都列成一个勾选框，自动认出的那些**先勾上**，用户自己增减
    - 认出来的判据：列名像链接（url / link / 海报 / 图片 / 封面 / poster / image）**且**该列的值里确实有链接；只看列名不算
    - 一列都不像 → **一个都不勾**（状态行提示「没认出来, 请自己勾」）—— 宁可让用户勾，也不偷偷拿一列错的当链接去下载
  - 「首行为字段名」勾选框：取消勾选则第一行也当数据，列名兜底成「字段1、字段2…」
- **海报地址**：默认 `<文档所在目录>\<命名来源首行值>-poster`
  - **改了「命名来源」→ 海报地址同步跟着变**（连用户手填的路径一起换掉 —— 用户要求两者同步）
  - 重新「开始分析」时，用户手改过地址就不覆盖
- **海报命名规则**：默认 `{partname}-{imgcol}`
  - `{partname}` = 该行的命名来源值；`{imgcol}` = **该链接字段自己的列名**（多字段时各用各的，如 `星穹计划-竖版海报.jpg` / `星穹计划-横版海报.jpg`）
  - 也认 `[partname]` / `[imgcol]` 的方括号写法
  - 文件名里的非法字符 `\ / : * ? " < > |` 换成 `_`
- **开始下载**：逐行 × 逐个勾上的链接字段取链接 → 按命名规则命名 → 存进海报地址
  - **按钮三态**：`开始下载` → 点它开始，按钮变 `下载中` → **再点一下 = 暂停**
    （正在下的那张下完就停，不再开始下一张），按钮变 `继续下载` → 再点继续 → 下完按钮回 `开始下载`
  - 扩展名：URL 后缀 → Content-Type → 兜底 `.jpg`
  - 海报目录**点「开始下载」时才建**（目录按需创建）
  - 同名文件**覆盖**
  - 单个失败**不中断整批**；结束报「成功 N · 失败 M」，末尾列前 3 条错误
  - 下载跑在后台线程，界面全程可动；关窗 = 取消（不杀正在跑的那一个请求）

## 4. 界面规格

### 4.1 主窗口布局

窗口标题 `视频检测v4.2`，初始几何 `1440x700`，最小 `1000x500`。

> 1440 而不是 1280：加「色彩」列后列宽总和 1347px，1280 的窗口装不下 → 主表格会出现
> 横向滚动条。1440 装得下（可用 ~1428px）。代价：1366px 宽的笔记本屏幕放不下。

```
┌ 文件路径: [____________] [浏览] [子文件夹] [开始检测] ┐
├ 码率标准: [____] kbps  采样率标准: [__] kHz    [清除记录][定点截图][下载海报] ┤
├──────────────────────────────────────────────────┤
│                    表格区                          │
├──────────────────────────────────────────────────┤
├ 迁移地址: [____________] [浏览]  [移动达标文件] [移动全部文件] ┤
├──────────────────────────────────────────────────┤
│ 状态栏（一行文字）                                   │
└──────────────────────────────────────────────────┘
```

- 行尾并排三个按钮：**「清除记录」→「定点截图」→「下载海报」**（2026-11-03 把「定点截图」挪到「清除记录」右边；2026-11-04 再加「下载海报」）
- 行尾右侧留 272px 的固定间距（272 是历史值，见 §6 #31）；行尾**最右**的按钮（现在是「下载海报」）的右边缘，与 Row 1 的「文件路径」输入框右边缘视觉对齐
- 状态栏是一行，凹陷边框；中间态只显示进度文字，终态追加统计

### 4.2 表格列定义

| # | key | 表头 | 默认宽 | 对齐 | 可排序 | 单元格内容 |
|---|---|---|---|---|---|---|
| 0 | — | `序号` | 45 固定 | 居中 | 否 | 1-based 行号，排序后按新位置 |
| 1 | `title` | `标题` | 300 | **左** | 否 | `./A/B/name.mp4` 或绝对全路径 |
| 2 | `resolution` | `分辨率` | 90 | 居中 | 否 | `1920x1080` / `N/A` |
| 3 | `frame_rate` | `帧率(fps)` | 100 | 居中 | **是** | `30.00` / `N/A` |
| 4 | `bitrate` | `码率(kbps)` | 110 | 居中 | **是** | `32000`（无小数无单位） |
| 5 | `spec` | `规格` | 160 | 居中 | 否 | `mp4 / h264 / aac`（分隔符前后各一个空格） |
| 6 | `audio_channels` | `声道数` | 55 | 居中 | 否 | `2` / `N/A` |
| 7 | `audio_sample_rate` | `采样率(kHz)` | 120 | 居中 | **是** | `48.0` / `N/A` |
| 8 | `color` | `色彩` | 142 | 居中 | 否 | `bt2020 / smpte2084`（颜色基准 / 颜色映射函数，ffprobe 原样） |
| 9 | `duration` | `时长` | 75 | 居中 | 否 | `00:01:00` / `N/A` |
| 10 | `file_size` | `文件大小` | 75 | 居中 | 否 | `1.0 GB` / `N/A` |
| 11 | `result` | `结果` | 75 | 居中 | **是** | `达标` / `不达标` |

**单位规则**：表头带单位，单元格不带（`帧率(fps)` ↔ `30.00`，`采样率(kHz)` ↔ `48.0`）。

**总宽** = 45（序号）+ 1302（11 个数据列）= **1347px**；默认窗口（1440px 宽）视口可用 1428px（有纵向滚动条时）→ 装得下，不出现横向滚动条（实测横向滚动条 max = 0，余量 81px）。

> **与 Tk 版的算式不是一回事**（换了东西，两个数字别直接比）：Tk 版的
> `45 + 995 + 9×10 = 1130px` 里那 `9×10` 是 **Tk 网格夹在列之间的拖拽手柄占位列**
> （`VideoGridView.GRAB_WIDTH = 10` —— 10 个数据列之间夹 9 个 10px 的 grab 列）。
> Qt 的 `QTableView` **没有这些占位列**：拖拽手柄画在表头格内部，不额外占宽
> → 这一项在 Qt 版里**不存在**，总宽就是各列宽之和。

**可排序列的宽度要装得下「表头文字 + 排序箭头」**：箭头是表头文字的**后缀**，会跟着列宽一起被像素截断（§6 #16），装不下的话排序箭头就被 `...` 吃掉（用户看不到排序态）。当前这组宽度按 10pt 字号实测得出（表头 + 箭头：帧率 69px / 码率 80px / 采样率 87px / 结果 44px，各留 ~20px 余量给不同平台的字体差异）。

**对齐规则只有两种**：`title` 左对齐，**其余全部居中**。

### 4.3 文案全集

**状态栏**
| 文案 | 触发 |
|---|---|
| `就绪` | 初始 |
| `正在扫描文件列表...` | 目录扫描开始 |
| `正在检测 {n} 个文件...` | 拖拽扫描开始 |
| `正在检测... ({i}/{total}) {文件名}` | 每个文件检测前 |
| `未找到视频文件` | 扫描正常结束，但目录里一个视频都没有（**不带统计**） |
| `检测完成：共 {N} · 达标 {P} · 不达标 {N-P}` | 扫描正常结束 |

| `已清除记录：共 0 · 达标 0 · 不达标 0` | 点「清除记录」 |

## 5. 数据规格

`VideoInfo` 每个字段的来源与兜底：

| 字段 | 来源 | 兜底 |
|---|---|---|
| `rel_path` | 相对源目录的路径，`/` 分隔 | 跨盘符时降级为绝对全路径 |
| `title` | `format.tags` 里的 `title`（大小写不敏感） | 文件名去扩展名 |
| `resolution` | 视频流宽×高 | 任一为 0 → `N/A` |
| `frame_rate` | `avg_frame_rate` 或 `r_frame_rate` | ≤0 或解析失败 → `N/A` |
| `bitrate_kbps` | 视频流 `bit_rate` 优先，其次 format 级 | 失败 → `0.0` |
| `video_codec` | 视频流 `codec_name` | `N/A` |
| `audio_codec` | 音频流 `codec_name` | 无音频流 → `N/A` |
| `audio_channels` | 音频流 `channels` | 无音频流 → `N/A` |
| `audio_sample_rate` | 音频流 `sample_rate` / 1000，一位小数 | 失败或无音频流 → `N/A` |
| `duration` | `format.duration` | 失败 → `N/A` |
| `file_size` | `format.size` | 失败 → `os.path.getsize` → 再失败 `N/A` |
| `container_format` | `format_name` 中匹配扩展名的 token | 首个 token → 扩展名 → `N/A` |
| `color_primaries` | 视频流 `color_primaries`（颜色基准） | 键不存在或为空 → `N/A`；ffprobe 报 `unknown` 就**原样存 `unknown`** |
| `color_transfer` | 视频流 `color_transfer`（颜色映射函数） | 同上 |
| `is_passing` | `bitrate >= 阈值 and sample_rate_passing` | — |
| `sample_rate_passing` | `hz/1000 >= 阈值` | 解析失败 → `False`；无音频流 → `True` |

## 6. 刻意保留的行为（重写时**不要顺手改**）

以下是历次迭代中**明确决定过**的行为。有些看着像 bug，但改掉是行为变更。

| # | 行为 | 原因 |
|---|---|---|
| 1 | 「共 N」（已出结果数）与「已完成 N/M」（找到的文件总数）来源不同 | 两者含义不同，不是矛盾 |
| 2 | 停止文案只保留一个冒号 | 旧文案 + 统计会出现两个冒号、两个「共」 |
| 3 | 迁移地址**无条件**转反斜杠，截图地址**仅 Windows**转 | 刻意的不对称：macOS 上反斜杠路径 `isdir`/`makedirs` 不认 |
| 4 | 帧率 ≤ 0 显示 `N/A` 而不是 `0.00` | 显示 `0.00` 会让用户以为视频真是 0 帧 |
| 5 | 无音频流 → 采样率视为达标 | 刻意的产品语义 |
| 6 | 阈值边界含等于 | 正好 30000 kbps 算达标 |
| 7 | 「浏览」只选文件夹，不选文件 | 旧的「先文件后文件夹」两段式已刻意删除；选文件只能拖拽 |
| 8 | 「浏览」选的是**父目录**，再套固定子目录 `snapshot` / `checked` | 与默认值同一套约定 |
| 9 | 迁移 / 截图地址**无条件**跟随源目录（覆盖用户手填） | 旧的「仅当为空才填」是 bug，已修 |
| 10 | 目录**按需创建** —— 扫描/浏览阶段绝不建目录 | 只有点「开始截图」/「移动」才建 |
| 11 | 手改「文件路径」立即丢弃拖拽的文件列表 | 不必先点「清除记录」 |
| 12 | 「规格」列合并三列、不可排序、不参与不达标着色 | 批量场景下三列几乎恒定；合并把横向余量从 9px 拉回 124px |
| 13 | 单位规则「表头带单位、cell 不带」 | 刻意统一 |
| 14 | 只有 `title` 列左对齐，其余全部居中 | 与早期设计稿（右对齐码率/采样率/大小）不同，**以现码为准** |
| 15 | 序号列固定 45px、不可排序、不可拖宽、永不染色 | 刻意 |
| 16 | 排序箭头是表头文字后缀，会随列宽被重新截断 | 刻意 |
| 17 | 排序稳定（同级保持插入顺序） | 刻意 |
| 18 | `result` 升序 → **不达标在前** | `False < True` |
| 19 | 扫描过程中结果按插入序追加；扫描结束后若处于排序态则统一重排一次 | 刻意 |
| 20 | 非可排序列点表头**完全无反应**（连光标都不变） | 刻意 |
| 21 | 列宽只存内存，不持久化 | 刻意 |
| 22 | 移动后表格不刷新 | 记为「与本期无关，另行处理」 |
| 23 | 目标重名时链式后缀（`a_1.mp4` → `a_1_1.mp4`） | 审计后接受现状 |
| 24 | 失败清单最多列 20 条 | 刻意 |
| 25 | 放大图从磁盘重新加载 640px 原图 | 为省内存 |
| 26 | 存盘是 640px PNG，弹窗显示 320px 缩略图 | 格式选择的结果 |
| 27 | 取消抽帧不 kill ffmpeg 进程 | 接受多抽 1~2 帧 |
| 28 | 截图弹窗**没有删除时间点按钮** | 清空输入框等价删除 |
| 29 | 截图弹窗默认时间点 `00:00:07:24` / `00:00:08:00` / `00:01:00:00` | 与设计稿不同，以现码为准；**2026-10-30 用户要求加第 3 个时间点**（默认 `00:01:00:00`），弹窗随之加宽到 1380px 让 3 张截图一屏放得下 |
| 30 | 「定点截图」按钮在 `kHz` 标签右侧 | 与设计稿位置不同，刻意 |
| 31 | 「清除记录」用硬编码 `padx=(0, 272)` | 视觉对齐的历史值 |
| 32 | 拖拽**立即开始扫描**，不需要再点「开始检测」 | 刻意 |
| 33 | 拖入目录不生效（只按扩展名过滤） | 刻意 |
| 34 | 拖入文件**不校验目录有效性** | 与「开始检测」路径不同，现状如此 |
| 35 | `_parse_drop_data` 不处理含空格的 macOS/Linux 路径 | 文档明说不在其能力范围 |
| 36 | `<Control-o>` 是唯一快捷键 | 其余无 |
| 37 | 帧率/码率等数值也参与像素截断 | 与文字统一处理 |
| 38 | Tooltip 用 `lift()` 而**非** `-topmost` | `-topmost` 是进程无关的，浮窗会浮在别的应用上面；`lift()` 只抬应用内的 sibling |
| 39 | Tooltip 的 `<Leave>` 是**延迟关闭** + 窗口**复用** | 跨 cell 移动时不闪；复用省掉每次重建 Toplevel（实测 4.4ms/次） |

> **注（Tk 版对照）**：上表 **#30 / #31 / #35 / #36 / #38 / #39** 这六条描述的是 **Tkinter 实现**（v3.3 及更早的代码）。在 Qt 版里对应的东西换了写法，不是照抄 Tk API —— 逐条对照如下：
>
> - **#30**「定点截图」按钮的位置 —— Tk 版放在 `kHz` 标签右侧；Qt 版现在在 Row 2 行尾（2026-11-03 挪到「清除记录」右边，2026-11-04 又在它右边加了「下载海报」）。**位置以现码为准**。
> - **#31**「清除记录」右对齐 —— Tk 版用硬编码 `padx=(0, 272)`；Qt 版在 Row 2 布局末尾加 `row2.addSpacing(272)`，间距值不变，仍是与 Row 1「文件路径」输入框右边缘的视觉对齐。**2026-11-03：「定点截图」挪到了「清除记录」右边**，所以现在与路径框对齐的是行尾最右的「定点截图」；间距值本身没动。
> - **#35** 拖放路径解析 —— Tk 版靠 `_parse_drop_data` 手工解析拖放文本，不处理含空格的 macOS/Linux 路径；Qt 版直接取 `event.mimeData().urls()` 再 `toLocalFile()`，Qt 交来的是 URL 对象，含空格的路径天然正确 —— 这条缺陷在 Qt 版不存在。
> - **#36** 唯一快捷键 —— Tk 版绑 `<Control-o>`；Qt 版是 `QShortcut(QKeySequence('Ctrl+O'))`，仍是全 app 唯一的快捷键。
> - **#38 / #39** Tooltip 的实现手法 —— Tk 版自建 Tooltip Toplevel：用 `lift()` 而非 `-topmost`，`<Leave>` 延迟关闭 + 窗口复用；Qt 版改用**原生 tooltip** —— 模型在 `Qt.ToolTipRole` 返回完整文本（仅在被截断时返回），浮窗层级、显示延时、跨 cell 移动时的表现全由 Qt 自己管。
>
> 其余 33 条是**行为级**描述（与 GUI 框架无关），Qt 版同样遵守。

## 7. 平台与打包要求

- **目标平台**：Windows 10/11
- **源码跨平台**：调 ffprobe / ffmpeg 时的 Windows 专有参数（`STARTUPINFO` / `CREATE_NO_WINDOW`）都有 `sys.platform == 'win32'` 守卫，源码可在 macOS/Linux 上跑；**打包目标仍是 Windows**。其中 **ffprobe 的守卫是 2026-10-27 才补上的**（见 §8 #1），ffmpeg（抽帧）的一直就有
- **ffprobe / ffmpeg**：优先用打包进 exe 的 `ffprobe\ffprobe.exe`（`sys._MEIPASS` 下），否则 `shutil.which`，再否则裸名字
- **隐藏控制台**：调 ffprobe/ffmpeg 时不弹黑框
- **打包**：PyInstaller **单文件** exe，`console=False`，产物名 `视频码率检查器.exe`
- **构建脚本** `build.bat` 负责：检查 Python → 缺 ffprobe 就下载 FFmpeg 并把 `bin/` 全拷进 `ffprobe/` → 装依赖 → 清 `build`/`dist` → 跑 PyInstaller
- **Python 版本**：源码用了 `X | None` 联合类型注解 → **实际需要 3.10+**
