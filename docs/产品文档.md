# 视频码率检查器 — 产品文档

版本: v3.3（与当前 `main` 一致）
日期: 2026-10-27
性质: **框架无关**的行为规格。任何实现（当前 Tkinter 版 / 未来的 PySide6 版）都必须满足本文。

---

## 1. 定位与用户

**一句话**：批量扫描视频文件，用 ffprobe 读出技术参数，按用户设定的阈值判定「达标 / 不达标」，并把文件批量移动到目标目录；另有一个定点截图功能，用于按时间点抽帧做肉眼比对。

**使用者**：做视频批量质检 / 归档的运营或后期人员。典型场景是手上有一大批待检文件，需要快速筛出达标的移走，不达标的留原地。

**平台**：Windows 桌面工具，打包成单文件 exe。当前实现只在 Windows 上能跑（见 §7）。

---

## 2. 核心概念

| 概念 | 含义 |
|---|---|
| **扫描** | 对一个目录（可递归）或一组被拖入的文件跑 ffprobe，产出每个文件的技术参数 |
| **达标** | 码率 **且** 采样率 **同时** 达标。两个阈值都满足才算达标 |
| **结果行** | 一个文件对应表格里的一行 |
| **派生路径** | 迁移地址 / 截图地址 —— 由「文件路径」派生出，默认各带一个固定子目录（`checked` / `snapshot`） |
| **定点截图** | 按若干时间点抽帧成 PNG，网格化展示供肉眼比对 |

## 3. 功能范围

### 3.1 扫描

- 输入：目录路径（配合「子文件夹」勾选决定是否递归）**或** 拖入窗口的一组文件
- 扩展名白名单 36 个（`.mp4 .mkv .avi .mov .wmv .flv .ts .m2ts .mpg .mpeg .webm .3gp .m4v .vob .ogv .rm .rmvb .asf .divx .f4v .mxf .mts .m1v .m2v .mpv .qt .y4m .nut .dv .tp .trp .hevc .h264 .h265 .264 .265`），比较大小写不敏感
- 递归用 `os.walk`（不跟随符号链接）；非递归用 `os.listdir`，**不排序**（保持系统顺序）
- 目录不存在或不可读 → 视为空结果，**不报错**
- 无视频流的文件 → 跳过（不进表格）
- ffprobe 失败 / 超时（30s）→ 静默跳过该文件，**不计入「共 N」，也不提示**
- 扫描过程可随时点「开始检测」取消（按钮变「正在停止…」）

### 3.2 达标判定

- 码率阈值默认 `30000` kbps，采样率阈值默认 `48` kHz，两者都可改
- 阈值必须是**正数**；非法输入弹错误框并拒绝开始扫描
- 判定：`bitrate_kbps >= 码率阈值` **且** `sample_rate_passing`
- **边界含等于**：正好 30000 kbps 算达标
- **无音频流视为采样率达标**（`sample_rate_passing = True`）
- 阈值是**扫描开始时的快照**：扫描中途改阈值，已扫的行不重算

### 3.3 表格展示

10 列，详见 §4.2。核心要求：

- 达标行**全部文字绿色**；不达标行**只有** title、result（+ 码率不达标时的 bitrate，+ 采样率不达标时的 audio_sample_rate）是红色，其余保持默认色
- **不画整行底色**，只有文字前景色
- 序号列固定 45px、不可排序、不可拖宽、**永不染色**
- 标题列显示相对路径 `./A/B/name.mp4`；跨盘符时显示绝对全路径
- 可排序列 4 个：结果 / 码率 / 帧率 / 采样率
- 点表头排序，**三态循环**：无 → 升序 → 降序 → 无；切到别的列重置为升序
- 排序箭头是**表头文字的后缀**（`码率(kbps) ▲` / `▼`），非活动列无箭头
- 列宽可拖拽调整，最小 20px；表头文字随列宽重新截断
- 文本过长按像素截断并加 `...`（三个 ASCII 点，不是 `…`）
- 悬停**被截断**的单元格才弹 tooltip 显示完整值；未截断的不弹

### 3.4 文件迁移

- 两个入口：「移动达标文件」/「移动全部文件」
- 目标目录**点按钮时才创建**（扫描与浏览阶段绝不建目录）
- 移动前弹确认框，列出数量与目标路径
- 目标已存在同名文件 → 追加 `_1`、`_2`… 直到不冲突
- 失败清单在结果框里列出，**最多 20 条**
- 移动的是**移动不是复制**
- 移动后表格不刷新（行仍显示旧路径）

### 3.5 定点截图

- 从主窗口「定点截图」按钮打开，模态
- 截图地址默认 `<文件路径>\snapshot`，可在弹窗内改；「浏览」选的是**父目录**，套一层 `snapshot`
- 默认 2 个时间点 `00:00:07:24` / `00:00:08:00`；`+` 按钮追加（默认 `00:00:00:00`）；**没有删除按钮**（清空输入框即删除）
- 时间点格式 `HH:MM:SS:frame`，MM/SS ∈ [0,59]
- 双击时间点输入框只选中所在的那一段（HH / MM / SS / frame），不整段全选
- 网格：行 = 文件，列 = 时间点；单元格显示抽出的帧
- 单元格三态：加载中（`…` 蓝）/ 成功（缩略图）/ 失败（`×` 红）
- 点已成功的缩略图 → 弹出放大窗口看 640px 原图（**从磁盘重新加载**，不是复用内存里的）
- 抽帧用 ffmpeg，输出 **640px 宽 PNG** 存盘，弹窗里显示 320px 缩略图
- 抽帧进行中点关闭 → 二次确认；**不 kill 已启动的 ffmpeg 进程**

### 3.6 拖拽文件

- 接收区域是**整个表格区**（含表头与正文），空表也能接住
- 拖入文件 → **立即开始扫描**（不需要再点「开始检测」）
- 路径框填第一个被拖入文件所在目录（不含文件名）
- 迁移地址 / 截图地址跟随该目录
- 记住拖入的**具体文件列表** → 下次点「开始检测」扫的是这批文件而非目录（除非用户手动改过路径框）
- **拒绝规则**：
  - 扫描中拖入 → 「正在检测中，请等待完成后再添加文件。」
  - 阈值非法 → 对应的错误框（与点「开始检测」同一套校验）
  - 全是非视频扩展名 → 「没有找到视频文件。」
  - 拖入**目录**不生效（只按扩展名过滤，目录没有扩展名）
- 非视频扩展名的文件**静默跳过**，不逐个提示

### 3.7 清除记录

点了会清：结果列表、表格内容、达标计数、**迁移地址**、**截图地址**、拖拽留下的文件列表。
点了**不会**清：码率 / 采样率阈值输入框。

扫描中点 → 「正在检测中，请等待完成后再清除。」

## 4. 界面规格

### 4.1 主窗口布局

窗口标题 `视频检测v3.3`，初始几何 `1280x700`，最小 `1000x500`。

```
┌ 文件路径: [____________] [浏览] [子文件夹] [开始检测] ┐
├ 码率标准: [____] kbps  采样率标准: [__] kHz  [定点截图]        [清除记录] ┤
├──────────────────────────────────────────────────┤
│                    表格区                          │
├──────────────────────────────────────────────────┤
├ 迁移地址: [____________] [浏览]  [移动达标文件] [移动全部文件] ┤
├──────────────────────────────────────────────────┤
│ 状态栏（一行文字）                                   │
└──────────────────────────────────────────────────┘
```

- 「清除记录」右对齐，用硬编码 `padx=(0, 272)` 与 Row 1 的「浏览」视觉对齐
- 「定点截图」在 `kHz` 标签右侧（不在「清除记录」旁）
- 状态栏是一行，凹陷边框；中间态只显示进度文字，终态追加统计

### 4.2 表格列定义

| # | key | 表头 | 默认宽 | 对齐 | 可排序 | 单元格内容 |
|---|---|---|---|---|---|---|
| 0 | — | `序号` | 45 固定 | 居中 | 否 | 1-based 行号，排序后按新位置 |
| 1 | `title` | `标题` | 250 | **左** | 否 | `./A/B/name.mp4` 或绝对全路径 |
| 2 | `resolution` | `分辨率` | 90 | 居中 | 否 | `1920x1080` / `N/A` |
| 3 | `frame_rate` | `帧率(fps)` | 75 | 居中 | **是** | `30.00` / `N/A` |
| 4 | `bitrate` | `码率(kbps)` | 85 | 居中 | **是** | `32000`（无小数无单位） |
| 5 | `spec` | `规格` | 140 | 居中 | 否 | `mp4/h264/aac` |
| 6 | `audio_channels` | `声道数` | 55 | 居中 | 否 | `2` / `N/A` |
| 7 | `audio_sample_rate` | `采样率(kHz)` | 90 | 居中 | **是** | `48.0` / `N/A` |
| 8 | `duration` | `时长` | 75 | 居中 | 否 | `00:01:00` / `N/A` |
| 9 | `file_size` | `文件大小` | 75 | 居中 | 否 | `1.0 GB` / `N/A` |
| 10 | `result` | `结果` | 60 | 居中 | **是** | `达标` / `不达标` |

**单位规则**：表头带单位，单元格不带（`帧率(fps)` ↔ `30.00`，`采样率(kHz)` ↔ `48.0`）。

**总宽** = 45 + 995 + 9×10 = **1130px**；默认窗口可用 1254px → 不出现横向滚动条。

**对齐规则只有两种**：`title` 左对齐，**其余全部居中**。

### 4.3 文案全集

**状态栏**
| 文案 | 触发 |
|---|---|
| `就绪` | 初始 |
| `正在扫描文件列表...` | 目录扫描开始 |
| `正在检测 {n} 个文件...` | 拖拽扫描开始 |
| `正在检测... ({i}/{total}) {文件名}` | 每个文件检测前 |
| `检测完成：共 {N} · 达标 {P} · 不达标 {N-P}` | 扫描正常结束 |
| `已停止检测（已完成 {done}/{queued}）：共 {N} · 达标 {P} · 不达标 {N-P}` | 扫描被取消 |
| `已清除记录：共 0 · 达标 0 · 不达标 0` | 点「清除记录」 |

分隔符是**全角冒号 `：`** 与**间隔号 `·`**（U+00B7）。

**弹窗**：`请输入有效的文件夹路径。` / `码率标准必须为正数。` / `采样率标准必须为正数。` / `正在检测中，请等待完成后再清除。` / `正在检测中, 请等待完成后再截图。` / `正在检测中，请等待完成后再添加文件。` / `没有找到视频文件。` / `请先扫描视频。` / `没有达标文件需要移动。` / `没有文件需要移动。` / `请输入目标文件夹路径。` / `无法创建目标目录:\n{e}` / `时间点格式错误: {e}` / `请输入至少一个时间点。` / `请先设置截图地址。` / `无法创建截图地址:\n{e}` / `抽帧还在进行中, 确定要关闭吗?`

**确认框**：`确定要将 {n} 个达标文件移动到:\n{dest}\n？` / `确定要将 {n} 个文件移动到:\n{dest}\n？` / `抽帧还在进行中, 确定要关闭吗?`

**结果框**：`成功移动 {n} 个文件。` + 可选 `\n\n{k} 个文件移动失败:\n` + 每行 `{相对路径}: {错误}`（最多 20 条）

**截图弹窗状态行**：`就绪 — 点「开始截图」开始` / `抽帧中 {done}/{total} ({当前文件名})` / `抽帧完成: {done}/{total} ({成功} 成功, {失败} 失败)` / `抽帧已取消: ...`

### 4.4 按钮状态

- **开始检测**：`开始检测` → 点按后变 `检测中`（**仍可点**，点即取消）→ 取消瞬间变 `正在停止...` 且禁用 → 结束恢复 `开始检测`
- **其余按钮从不禁用**，靠弹窗拒绝（这是现状，重写可保持或改好，但要在 changelog 里写明）

## 5. 数据规格

`VideoInfo` 每个字段的来源与兜底：

| 字段 | 来源 | 兜底 |
|---|---|---|
| `rel_path` | 相对源目录的路径，`/` 分隔 | 跨盘符时降级为绝对全路径 |
| `title` | `format.tags` 里的 `title`（大小写不敏感） | 文件名去扩展名 |
| `resolution` | 视频流宽×高 | 任一为 0 → `N/A` |
| `frame_rate` | `avg_frame_rate` 或 `r_frame_rate` | ≤0 或解析失败 → `N/A` |
| `bitrate_kbps` | 视频流 `bit_rate` 优先，其次 format 级 | 失败 → `0.0` |
| `video_codec` | 视频流 `codec_name` | `N/A` |
| `audio_codec` | 音频流 `codec_name` | 无音频流 → `N/A` |
| `audio_channels` | 音频流 `channels` | 无音频流 → `N/A` |
| `audio_sample_rate` | 音频流 `sample_rate` / 1000，一位小数 | 失败或无音频流 → `N/A` |
| `duration` | `format.duration` | 失败 → `N/A` |
| `file_size` | `format.size` | 失败 → `os.path.getsize` → 再失败 `N/A` |
| `container_format` | `format_name` 中匹配扩展名的 token | 首个 token → 扩展名 → `N/A` |
| `is_passing` | `bitrate >= 阈值 and sample_rate_passing` | — |
| `sample_rate_passing` | `hz/1000 >= 阈值` | 解析失败 → `False`；无音频流 → `True` |

## 6. 刻意保留的行为（重写时**不要顺手改**）

以下是历次迭代中**明确决定过**的行为。有些看着像 bug，但改掉是行为变更。

| # | 行为 | 原因 |
|---|---|---|
| 1 | 「共 N」（已出结果数）与「已完成 N/M」（找到的文件总数）来源不同 | 两者含义不同，不是矛盾 |
| 2 | 停止文案只保留一个冒号 | 旧文案 + 统计会出现两个冒号、两个「共」 |
| 3 | 迁移地址**无条件**转反斜杠，截图地址**仅 Windows**转 | 刻意的不对称：macOS 上反斜杠路径 `isdir`/`makedirs` 不认 |
| 4 | 帧率 ≤ 0 显示 `N/A` 而不是 `0.00` | 显示 `0.00` 会让用户以为视频真是 0 帧 |
| 5 | 无音频流 → 采样率视为达标 | 刻意的产品语义 |
| 6 | 阈值边界含等于 | 正好 30000 kbps 算达标 |
| 7 | 「浏览」只选文件夹，不选文件 | 旧的「先文件后文件夹」两段式已刻意删除；选文件只能拖拽 |
| 8 | 「浏览」选的是**父目录**，再套固定子目录 `snapshot` / `checked` | 与默认值同一套约定 |
| 9 | 迁移 / 截图地址**无条件**跟随源目录（覆盖用户手填） | 旧的「仅当为空才填」是 bug，已修 |
| 10 | 目录**按需创建** —— 扫描/浏览阶段绝不建目录 | 只有点「开始截图」/「移动」才建 |
| 11 | 手改「文件路径」立即丢弃拖拽的文件列表 | 不必先点「清除记录」 |
| 12 | 「规格」列合并三列、不可排序、不参与不达标着色 | 批量场景下三列几乎恒定；合并把横向余量从 9px 拉回 124px |
| 13 | 单位规则「表头带单位、cell 不带」 | 刻意统一 |
| 14 | 只有 `title` 列左对齐，其余全部居中 | 与早期设计稿（右对齐码率/采样率/大小）不同，**以现码为准** |
| 15 | 序号列固定 45px、不可排序、不可拖宽、永不染色 | 刻意 |
| 16 | 排序箭头是表头文字后缀，会随列宽被重新截断 | 刻意 |
| 17 | 排序稳定（同级保持插入顺序） | 刻意 |
| 18 | `result` 升序 → **不达标在前** | `False < True` |
| 19 | 扫描过程中结果按插入序追加；扫描结束后若处于排序态则统一重排一次 | 刻意 |
| 20 | 非可排序列点表头**完全无反应**（连光标都不变） | 刻意 |
| 21 | 列宽只存内存，不持久化 | 刻意 |
| 22 | 移动后表格不刷新 | 记为「与本期无关，另行处理」 |
| 23 | 目标重名时链式后缀（`a_1.mp4` → `a_1_1.mp4`） | 审计后接受现状 |
| 24 | 失败清单最多列 20 条 | 刻意 |
| 25 | 放大图从磁盘重新加载 640px 原图 | 为省内存 |
| 26 | 存盘是 640px PNG，弹窗显示 320px 缩略图 | 格式选择的结果 |
| 27 | 取消抽帧不 kill ffmpeg 进程 | 接受多抽 1~2 帧 |
| 28 | 截图弹窗**没有删除时间点按钮** | 清空输入框等价删除 |
| 29 | 截图弹窗默认时间点 `00:00:07:24` / `00:00:08:00` | 与设计稿不同，以现码为准 |
| 30 | 「定点截图」按钮在 `kHz` 标签右侧 | 与设计稿位置不同，刻意 |
| 31 | 「清除记录」用硬编码 `padx=(0, 272)` | 视觉对齐的历史值 |
| 32 | 拖拽**立即开始扫描**，不需要再点「开始检测」 | 刻意 |
| 33 | 拖入目录不生效（只按扩展名过滤） | 刻意 |
| 34 | 拖入文件**不校验目录有效性** | 与「开始检测」路径不同，现状如此 |
| 35 | `_parse_drop_data` 不处理含空格的 macOS/Linux 路径 | 文档明说不在其能力范围 |
| 36 | `<Control-o>` 是唯一快捷键 | 其余无 |
| 37 | 帧率/码率等数值也参与像素截断 | 与文字统一处理 |
| 38 | Tooltip 用 `lift()` 而**非** `-topmost` | `-topmost` 是进程无关的，浮窗会浮在别的应用上面；`lift()` 只抬应用内的 sibling |
| 39 | Tooltip 的 `<Leave>` 是**延迟关闭** + 窗口**复用** | 跨 cell 移动时不闪；复用省掉每次重建 Toplevel（实测 4.4ms/次） |

## 7. 平台与打包要求

- **目标平台**：Windows 10/11
- **ffprobe / ffmpeg**：优先用打包进 exe 的 `ffprobe\ffprobe.exe`（`sys._MEIPASS` 下），否则 `shutil.which`，再否则裸名字
- **隐藏控制台**：调 ffprobe/ffmpeg 时不弹黑框
- **打包**：PyInstaller **单文件** exe，`console=False`，产物名 `视频码率检查器.exe`
- **构建脚本** `build.bat` 负责：检查 Python → 缺 ffprobe 就下载 FFmpeg 并把 `bin/` 全拷进 `ffprobe/` → 装依赖 → 清 `build`/`dist` → 跑 PyInstaller
- **Python 版本**：源码用了 `X | None` 联合类型注解 → **实际需要 3.10+**

| # | 缺陷 | 影响 |
|---|---|---|
| 1 | `run_ffprobe` 无条件构造 Windows 专用的 `STARTUPINFO` / `CREATE_NO_WINDOW` | **macOS/Linux 上 worker 线程直接崩**，UI 永久卡在「检测中」。实际后果：**这个 app 目前只能在 Windows 上跑** |
| 2 | 阈值解析接受 `inf` / `nan`（`float()` 通过且 `> 0` 成立） | 所有行永远不达标 |
| 3 | 「未找到视频文件」的状态文案会被紧随其后的完成逻辑立刻覆盖 | 用户永远看不到这条提示 |
| 4 | 移动按钮在扫描中不禁用 | 可在扫描中途触发移动 |
| 5 | 目标重名时链式后缀 | `a_1.mp4` 冲突 → `a_1_1.mp4` |
| 6 | 「移动」后表格不刷新 | 行仍显示旧路径 |

## 9. 验收方式

现有 **12 个一次性断言脚本**（`docs/superpowers/specs/*-assertions.py`）是机器可读的回归基线。

**注意**：这些脚本大量断言 **Tkinter 内部结构**（`winfo_manager()`、`_widget_pool`、`grid_columnconfigure` 的 minsize、`_cells` 布局、`hsb.master is _middle`）。**换框架后不能原样复用**，但每条断言背后的**用户可见语义**必须逐条落到新实现上 —— 重写时应把它们改写为「用户可见行为」的断言。
